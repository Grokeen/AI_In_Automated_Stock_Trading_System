## 1. 운영자가 따라갈 순서

1. **설정 확인**: 실행 모드(`offline` 또는 `paper`), 브로커 환경, 필수 위험 한도, 영속 저장 경로를 읽는다. 비밀 값 자체는 화면·CLI·상태 JSON에 표시하지 않는다. 누락·환경 불일치·한도 미설정·저장 경로 쓰기 불가는 시작 실패 또는 새 주문 차단으로 표시한다.
2. **모드 선택**: `offline`은 네트워크·자격 증명 없이 고정된 가짜 브로커로 동작 확인하는 모드다. `paper`는 브로커의 모의 환경에 연결하는 모드다. 모드 값이 명시되지 않거나 paper 인증이 부족하면 offline/paper 중 하나를 자동 선택하지 않고 시작을 거부한다. 실환경으로 자동 전환하지 않는다.
3. **연결·초기 조회**: paper는 모의 환경 연결, 인증, 시세·계좌·미체결 주문 조회를 순서대로 수행한다. offline은 가짜 브로커 응답을 사용하고 외부 연결 상태를 `not_applicable`로 표시한다. 연결과 계좌 조회만으로 새 주문 허용을 선언하지 않는다.
4. **복구·대사**: 저장된 주문과 브로커 주문·체결을 대조한다. 결과 불명·미대사 주문이 있으면 새 노출을 만드는 주문을 막고, 조회 결과와 다음 확인 시점을 표시한다. 저장 오류가 있으면 상태 기록부터 복구하기 전까지 주문 전송을 막는다.
5. **운영 상태 확인**: 모드, 시세·계좌·대사 마지막 성공 시각, 미체결 수, 저장 상태, 새 주문 허용 여부와 사유를 확인한다. 오래된 데이터는 값과 수신 시각을 함께 표시한다.
6. **중지·복구**: `새 주문 중지`는 이후 신규 주문 전송을 막는다. 이미 접수된 미체결은 그대로 남고 보유 주식도 그대로 유지된다. 필요하면 별도로 `미체결 취소`를 요청하고 각 주문의 취소 최종 결과를 확인한다. `보유 청산`은 현재 보유분을 매도하는 별도 위험 동작으로, 명시적 별도 요청과 위험 검사 없이 자동 실행하지 않는다.

## 2. 입력과 출력 계약 (DEV 인계)

| 동작 | 입력 | 출력·기록 | 실패 시 동작 |
|---|---|---|---|
| 시작 / 모드 확인 | 명시적 모드, 설정 검증 결과, 설정 식별자 | 선택 모드, 설정 유효 여부, 실행 세션 ID | 모드 누락·불일치·필수 한도 누락은 시작 거부. 비밀값은 출력하지 않음 |
| 연결 및 조회 | 브로커 어댑터, 요청 시각, timeout | 연결 상태, 시세/계좌 스냅샷과 각각의 수신 시각 | timeout·오류는 stale/ disconnected 표시; 마지막 성공 시각 보존 |
| 새 주문 판정 | 모드, 데이터 신선도, 계좌 유효성, 위험 한도, 저장 가능 여부, 대사 상태, 운영자 중지 플래그 | `new_orders_allowed` 불리언 및 기계 판독 가능한 `stop_reasons[]` | 어떤 필수 조건이 불확실해도 false로 닫힘 |
| 주문 전송 | 주문 의도 ID, 종목·방향·수량·가격 조건, 승인 결과 | 내부 주문 ID, 브로커 주문 ID(확보 시), 상태·시각 | 응답 누락은 결과 불명으로 저장. 대사 전 동일 의도 재전송 금지 |
| 취소 요청 | 내부/브로커 주문 ID, 운영자 취소 요청 | 취소 요청 접수와 최종 취소/거절 상태를 각각 기록 | 접수 응답을 취소 완료로 표시하지 않음. 부분체결·잔량 분리 반영 |
| 복구·대사 | 로컬 주문 기록, 브로커 조회 결과, 실행 세션 | 일치/불일치/미확정 판정, 확인 시각, 주문별 조치 | 미확정은 새 주문 차단 유지; 주문이 안 보인다는 사실만으로 실패 확정 금지 |
| 저장 검사·쓰기 | DB 경로, 트랜잭션 내용, 읽기/쓰기 결과 | 저장소 상태와 마지막 성공 시각 | 쓰기 실패 시 새 주문 차단, 메모리 상태만으로 성공 처리하지 않음 |

## 3. 재현 가능한 확인 시나리오

각 시나리오는 가짜 브로커와 고정 시각을 사용한다. 명령 이름은 DEV가 구현할 실행 경로에 맞춰 제공하며, 이 문서는 아직 존재하지 않는 CLI를 가정하지 않는다. 기대 출력은 상태 JSON/CLI에 동일한 의미로 표현한다.

| ID | 주입 입력·조건 | 기대 표시·행동 |
|---|---|---|
| OF-01 정상 offline | 모드 offline, 유효 설정·저장소, 최신 가짜 시세·계좌, 빈 대사 결과 | `mode=offline`, 연결 `not_applicable`, 시각·미체결 `0` 표시. 조건이 모두 충족될 때만 새 주문 허용 |
| OF-02 정상 paper | 모드 paper, 일치하는 모의 자격 증명, 연결·시세·계좌·대사 성공 | `mode=paper`; 각 성공 시각과 미체결 수 표시. 운영자 중지/위험 차단이 없을 때 허용 |
| OF-03 지연 시세 | 마지막 시세 시각이 신선도 한도보다 오래됨 | `market_data=stale`, 마지막 수신 시각 표시, `new_orders_allowed=false`, 사유 `STALE_MARKET_DATA` |
| OF-04 단절 | 요청 timeout 후 연결 끊김, 과거 시세·계좌 스냅샷 존재 | 연결 단절과 마지막 성공 시각을 함께 표시. 재연결 전 신규 주문 차단; 무한 재시도 금지 |
| OF-05 결과 불명 | 주문 요청 전송 후 응답 timeout, 브로커 주문 ID 미확인 | 로컬 주문 `UNKNOWN`/결과 불명, 대사 필요 표시. 같은 의도 재전송 금지, 새 주문 차단 |
| OF-06 복구 완료 | OF-05 기록이 있고 재시작 뒤 브로커 조회에서 해당 주문·체결 확인 | 로컬-브로커 대사 결과와 시각을 기록. 결과가 확정되고 다른 게이트도 통과해야 새 주문 허용 |
| OF-07 대사 미확정 | 로컬 기록과 브로커 조회가 불일치 또는 주문 조회 결과 부족 | 미확정 주문과 다음 조치 표시, 해당 주문 재전송 금지, 새 노출 주문 차단 유지 |
| OF-08 저장 실패 | 주문 의도 또는 상태 트랜잭션 쓰기에서 I/O 오류 | 저장소 오류와 마지막 성공 시각 표시. 주문 전송 차단; 이미 전송 후 쓰기 실패면 결과 불명으로 취급하고 조회·대사 필요 |
| OF-09 중지 의미 | 신규 주문 1건 전 운영자 중지 플래그 켜기, 미체결 2건·보유 종목 1개 | 새 주문 허용 false. 미체결 2건 및 보유 1개 보존; 취소·청산 자동 실행 없음 |
| OF-10 취소와 청산 분리 | OF-09에서 미체결 취소만 별도 요청 | 미체결 각각 취소 진행/최종 결과 표시, 보유 수량은 변경 없음. 청산은 별도 명시 요청 없이는 실행 안 됨 |
| OF-11 설정 오류 | paper 모드에 다른 환경의 자격 증명 또는 필수 위험 한도 누락 | 설정 오류를 필드명·코드로 표시, 비밀값은 마스킹, 시작 거부 또는 새 주문 불허 |

## 4. 구현 시 해석 규칙

- `새 주문 중지`는 신규 주문 전송 게이트를 닫는 상태 변경이다. 이미 전송한 주문을 되돌리거나 취소하지 않는다.
- `미체결 취소`는 브로커에 취소를 요청하는 개별 주문 동작이다. 취소 요청 수락과 잔량의 최종 취소 확인을 구분한다.
- `보유 청산`은 보유 포지션을 줄이거나 매도 주문을 내는 별도 실행 동작이다. 자동 중지·통신 복구·저장 실패의 기본 대응으로 사용하지 않는다.
- 결과 불명 주문, 미대사 주문, stale 계좌/시세, 위험 한도 불충족, 저장 불능, 운영자 중지 중 하나라도 있으면 신규 주문 허용은 false다.
- 오류가 회복되어도 시각과 원인을 기록하고 재조회·대사 성공을 확인한 뒤 게이트를 다시 평가한다. 장애가 사라진 것으로 추정해 자동으로 미확정 주문을 재전송하지 않는다.
