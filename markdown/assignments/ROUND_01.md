## 2. 파일 소유와 통합

- CD2는 `trading/`와 새 매매 테스트, CD3는 `markdown/design/`, CD4는 `markdown/research/`, CD5는 시작·팀 상태 안내와 README·UPDATE·OWERORDER를 담당한다.
- CD1은 이번 임무 지시서·분장표·`markdown/audit/`·`reports/reviews/`를 담당한다. 요청서·정의서·개발 방법의 범위 변경은 제안과 근거로 제출하고 동시에 덮어쓰지 않는다.
- `reports/review_requests/<담당자>_R1.md`와 `reports/verification/<담당자>_R1/`는 각 담당자의 독립 경로다. 예: `CD2_R1.md`.
- 첫 지시 전 CD1이 공통 배정 기록을 반영한다. 이후 이번 라운드 공통 이력 파일의 물리적 수정은 CD5가 모아 수행한다. 모든 담당자는 자기 검증 요청서에 작업·검증 내역을 적고 공통 기록 누락 여부를 확인한다.
- 공유 폴더의 기존 `.git`·잠금을 변경하지 않는다. 격리된 Git 메타데이터나 정상 checkout에서 역할별 브랜치를 사용할 수 있으나 main에 직접 통합하거나 NAS에 설치하지 않는다. 검증한 커밋 또는 대상 파일 SHA-256을 제출하며 통합은 CD1이 조율한다.

## 3. 자체 검증 후 CD1에게 요청

검증 요청서는 최소 다음을 포함한다.

```text
담당자 / 업무 ID / R1:
관련 요구사항 / 완료 범위:
기준 커밋 / 변경 파일 / 제출 커밋 또는 SHA-256:
실행 환경 / 명령 / 실제 결과 / 근거 파일:
성공·실패·복구 또는 문서·출처 확인 시나리오:
미검증·미지원·남은 문제 / 선행 입력:
CD1이 재현할 방법:
요청 판정 범위:
```

명령을 실행하지 않았으면 실행했다고 적지 않는다. Windows의 Linux 테스트 제외와 실제 NAS 미검증을 구분한다. 오류를 고친 뒤 관련 검사를 다시 수행한다. 문서·디자인·연구는 링크·일관성·상태·출처·요구 추적 등의 해당 검사를 수행한다.

완료 후 사용자 지시에 근거해 **CD1 / 감사 담당** 채팅으로 검증 요청서 경로와 요약을 전달한다. 회신 권한은 CD1의 전달 문구만으로 추정하지 않고, 원본 CD1 채팅의 사용자 직접 지시를 확인한다. 원본 확인이 어려우면 요청서를 남기고 본인 채팅에서 완료·전달 불가 상태를 보고한다.

## 4. CD1 판정과 진행 상태

- 자체 검증 완료 → CD1 검증 요청 → CD1 재현·근거 확인 → 확인 완료 / 보완 요청 / 근거 부족으로 검증 보류.
- CD1 확인 전에는 `검토 대기`로 표시하며 담당자의 자체 검사 통과와 구분한다.
- 보완 요청에는 영향·재현 조건·요구 수정·재검증 범위를 적는다. 보완한 담당자는 갱신된 근거로 다시 요청한다.
- 사용자 결정이 필요한 범위·계좌·자금 관련 사항과 일반 구현 결정을 구분해 보고한다.
