## 1. 요청 배경과 목표

사용자는 Raspberry Pi 4로 구성한 NAS를 파일 저장·공유·백업 용도로 계속 사용하면서, 남는 자원으로 주식 자동매매 시스템을 운영하고자 한다. 증권사와 개발 방식에 익숙하지 않아 후보 조사와 기술적 구성을 요청했다.

목표는 NAS의 기존 기능을 유지하면서 시세 수집, 전략 판단, 주문·체결 관리, 운영 상태 확인을 수행할 수 있는 가벼운 시스템을 만드는 것이다. 초기에는 모의투자로 동작과 장애 복구를 검증한다. AI 활용은 이후 확장 목표이며, 수익률 보장이나 특정 종목 매수·매도 추천은 이 요청의 완료 기준이 아니다.

이번 문서 작성 요청은 개발 작업을 인계하기 위한 것이다. 이 문서 자체가 계좌 개설, 자금 투입 또는 실제 매매 실행을 지시하지는 않는다.

### 4.2 이후 확장

- PC 또는 별도 연산 환경에서 AI 모델 학습·백테스트를 수행하고, NAS에는 가벼운 추론 또는 사전에 만든 신호만 전달한다.
- AI 모델의 학습 데이터, 버전, 검증 구간, 거래비용 가정을 기록한다. AI 신호도 동일한 위험 한도 검사를 거친다.
- 해외주식, 추가 증권사, 웹 대시보드, 외부 알림은 필요성이 확인되면 범위를 구체화한다.

### 4.3 초기 범위에서 제외

- 실제 자금 투입과 실계좌 주문 실행.
- 파생상품·신용·레버리지 거래, 초저지연 고빈도 매매.
- NAS에서의 대규모 AI 학습과 대량 백테스트.
- 사용자 파일의 정리·이동·삭제, 저장장치 포맷, NAS OS 교체·업그레이드, 부팅 설정 변경.

이 항목들은 기존 NAS 최적화 작업의 허용 범위를 확대해 해석하지 않는다. 실거래 운영 설정과 계좌·자금 관련 결정은 사용자가 직접 검토하고 수행할 별도 단계다.

## 5. 비기능 요구사항

- 현재 장비의 32비트 사용자 환경에서 동작하는 가벼운 구성을 우선한다. 커널이 aarch64라는 이유로 arm64 전용 패키지나 이미지를 선택하지 않는다.
- 준비된 자원 한도를 사용하되 `LimitAS`를 전체 프로세스의 실제 메모리 합계 제한으로 설명하지 않는다.
- 시세·조회 호출을 무제한 반복하지 않는다. 증권사·계좌별 최신 호출 한도를 확인하고 공통 속도 제한과 재연결 제어를 적용한다.
- 주문 타임아웃을 실패 확정으로 간주해 무조건 재전송하지 않는다. 결과 불명 상태에서는 계좌·주문 조회로 확인한다.
- 거래 기록은 영속 저장소에 두고, RAM 임시 경로와 공유 NTFS 볼륨을 주문 DB의 기본 경로로 사용하지 않는다.
- 한국 시간으로 운영 일정을 해석하고 저장 데이터에는 시간대가 있는 시각을 사용한다.
- 기존 테스트의 의미를 보존하고 새로운 핵심 동작·장애 복구에 필요한 검증을 추가한다.

3. 변경한 동작에 맞는 검증을 수행하고, 실행한 검사·결과·검증하지 못한 항목을 구분해 기록한다.
